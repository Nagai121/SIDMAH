# Query Outputs Schema

## 出力単位と保存場所

Queryごとに`query_outputs/`直下に専用ディレクトリを一つ設け、最終成果物をそこへまとめる。ディレクトリ名はQueryを区別できる重複のないものとし、既存Queryの成果物を上書きしない。厳密な命名形式は指定しない。`outputs_schema.md`自体は出力成果物に含めない。

各Queryディレクトリには必ず`report.md`を作成する。図、グラフ、画像、CSV、JSON、コード、補足文書などは必要に応じて任意の形式・名前・個数で追加でき、サブディレクトリの利用も認める。`report.md`は成果物の入口とし、関連するファイルを相対パスで参照できるようにする。図表を本文へ埋め込んでもよい。

## report.md

科学論文・実験レポートに準じ、原則としてTitle、Abstract、Introduction、Methods、Results、Discussion、Conclusion、Referencesを標準構成とする。研究分野やQueryの性質に応じて節の追加、統合、細分化、再構成を認める。構成を変更しても、研究目的、方法、結果、考察、結論、根拠の追跡可能性を維持する。文章量や図表の形式は内容に応じて決め、同じ情報を不要に繰り返さない。

レポートにはQueryの目的と達成条件、それに対する回答、採用した結果と根拠、必要な実験間の統合・比較、信頼性と限界、異常や判断不能の範囲を含める。実験を実行できたこととQueryの目的を達成したことを区別し、達成できなかった場合は理由と未達成項目を明記する。必要な参考文献や外部データの出典も示す。Query外の派生疑問を新たな目的として加えず、検証した範囲を越えて主張しない。

## 成果物と根拠の対応

本文で用いる図表や補足資料には、何を示すものか分かる説明と参照を付ける。採用した結果については、対応するRuntime、入力、条件、結果ファイルや監査記録などの原本を特定できるようにする。複数Runtimeを統合した場合も、どの結果を採用したか追跡可能にする。

`works/`内のSnapshot、Result、実行ログなどは既存の管理場所を維持し、必要な場合は原本への参照を示す。大容量の原本をQueryディレクトリへ複製することは要求しない。Field Controlの結果をQuery回答用の実験結果として数えない。

成果物を確認してユーザーへ提示し、ユーザーの同意を得てQueryを完了する。
